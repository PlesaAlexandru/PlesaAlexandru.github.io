**PROCESS AND NOTES:**  

Understand the alert:  
	The alert was created because the email contains one or more external links with suspicious characteristics. We are also told to check the endpoints and firewall or proxy logs but we are limited by the simulation and can't do that. The alert is only saying that it was received but we are not sure if the host pressed the button from the email.  

URL Analysis:  
The setup button have the linked URL: `https[:]//hrconnex.thm/onboarding/15400654060/j.garcia`
which includes the receiver real name (j.garcia), the real domain (hrconnex.thm) and the real cause (onboarding).  

With limited access, we cannot view the endpoints, logs, history of any form, so due to the fact that the email looks like an request to complete to Setup the profile on TheTryDaily.  

The URL wasn't accessible, maybe due to the introductory simulation. So the final evidence we could theoretically gather would be to get an answer if the host really signed up on the website. But again, without SPF, DKIM, DMARC or contacting the host, we can only access the face value of the mail and the given detection tool.  

![](../../assets/Pasted%20image%2020261013020518.png)

With that being mentioned, final verdict is:  
<Success>FALSE POSITIVE, no escalation needed</Success>

Understand the alert:  
	The alert was created because when a user attempted to access an external URL that is listed in the organization's blacklist or threat intelligence feeds. Which means the damage was done. Based on the findings an host training might be necessary.

**IP Checks:**
Internal platform
![684](../../assets/Pasted%20image%2020261013002706.png)
  
The internal platform finds the IP as being **MALICIOUS**. Which is already a huge red flag. But for more information, I also used different platforms that are used for IP analysis to make more evidence based decision. So, below you can see listed some platforms and their results.  

Abuseipdb.com  
![454](../../assets/Pasted%20image%2020261013001424.png)  
  
The IP belongs to `bit[.]ly` which is a legitimate service.  
Result: 29% Elevated, with 72 reports just in the last 2 weeks. Which confirms the suspicion about it being Malicious, because bit[.]ly is used as a scamming method, and in the end an True Positive (TP) case. 

![](../../assets/Pasted%20image%2020261013032420.png)  
<cite>Source:https[:]//www.researchgate.net/publication/263163925_bitlymalicious_Deep_Dive_into_Short_URL_based_e-Crime_Detection</cite>

Let's use other 2 platforms just for the sake of learning.  
  
VirusTotal:  
![](../../assets/Pasted%20image%2020261013001450.png)
  
Result: One finding of it being an IP used for Phishing attacks. We can also try to access the URL  directly in an isolated envoierment.   

Direct Access to the bit[.]ly link via browserling.com
![](../../assets/Pasted%20image%2020261013001737.png)
Result: The URL is not accessible via direct connection due to it being sent by an suspended account.  

After a quick analysis, we can already tell there are a lot of huge red flags, such as:  
- Shortening an URL for no reason given.    
- All indicators reveal the fact that the IP is Malicious, but worth noting the fact that the IP is marked as being Malicious due to the nature of bit[.]ly as a service.
- The suspended account on bit[.]ly. 

Final verdict, with limited tools for verifications, is:

<Error>TRUE POSITIVE, no escalation, training the host is recommanded. </Error>

**PROCESS AND NOTES:**  

Understand the alert:  
	The alert was created because the email contains one or more external links with suspicious characteristics. We are also told to check the endpoints and firewall or proxy logs but we are limited by the simulation and can't do that. The alert is only saying that it was received but we are not sure if the host pressed the button from the email.  

URL Analysis:  
The setup button have the linked URL: `https[:]//hrconnex.thm/onboarding/15400654060/j.garcia`
which includes the receiver real name (j.garcia), the real domain (hrconnex.thm) and the real cause (onboarding).  

With limited access, we cannot view the endpoints, logs, history of any form, so due to the fact that the email looks like an request to complete to Setup the profile on TheTryDaily.  

The URL wasn't accessible, maybe due to the introductory simulation. So the final evidence we could theoretically gather would be to get an answer if the host really signed up on the website. But again, without SPF, DKIM, DMARC or contacting the host, we can only access the face value of the mail and the given detection tool.

With that being mentioned, final verdict is:

> **direction:** inbound  

Understand the alert:  
	The alert was generated because n inbound email contains one or more external links due to potentially suspicious characteristics. We can already see the luring aspect of the mail but it is common practice for the "Unusual activity email" to appear in cases where your account is compromised.

So, we can already spot the typo (m1crosoftsupport[.]co) from the sender (no-reply@m1crosoftsupport[.]co), which is already a confirmation of the luring aspect of urgency mentioned before. The attacker is trying to lure the target with similar looking domains and uncertainty of "unusual activity". The attacker also attached the location and IP Address(102[.]89[.]222[.]143) and location (Nigeria), we can do a quick search for the IP provided, just to see if the information inside the email looks legitimate, but we need to mention that the IP is not the sender's IP, it is part of the scam.

> **direction:** inbound  

Understand the alert:  
	The alert was triggered because n inbound email contains one or more external links due to potentially suspicious characteristics. As the last alert, the attacker looks like it is using urgency ("we don’t hear from you within 48 hours, your package will be returned to sender") which could be an legitimate email, we have to look at the evidence and decide if it is legit or just abusing urgency for the clicks.  

Sender (urgents@amazon[.]biz) is using an legitimate service (Amazon) to impersonate the real company and it's practices. Amazon doesn't use urgents@amazon[.]biz for this type of problems as seen in the screenshot below:
![](../../assets/Pasted%20image%2020261013141416.png)
Our sender email is .biz instead of .com

Another aspect to look for, the link is a shortened form link, which is absolutely not necessary for a company like amazon. At the first glance we can see it is the exact same shortened link as we analyzed before.

ALERT #8816:

With that being said, the sender domain is not an legitimate Amazon domain for emails. Amazon uses .com instead of .biz, even if they use amazon.biz to redirect the user to amazon.com, sender email stays consistent due to internal regulations. Also, the link provided for the action is the exact same link as the alert before, which brings more attention to the second attempt of the attacker. With limited checking and resources, we can only inspect it but the URL should be immediately blocked or put on a blacklist.
